# 07 前端设计

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 团队通用 |
| 组件库 | **Arco Design**（`@arco-design/web-react`） | 火山系设计语言，对齐控制台最省力 |
| 路由 | React Router 6 | 深链需要真实 URL |
| 数据层 | TanStack Query | 轮询、缓存失效、乐观更新都是现成的 |
| 构建 | Vite | 产物是纯静态，交给 Daemon serve |
| 图表 | ECharts（Arco 生态） | 技能分布、延迟分布、同步曲线、通过率 |
| 语言 | 界面中文，仅亮色主题 | 需求明确 |

**前端零业务状态**（D17）：所有状态读自 API，
本地只存 UI 偏好（列宽、折叠、每页条数、上次选的筛选项）。刷新页面不丢任何东西。

### 2.1 深链（契约不变）

`/tasks/new` 必须接受 v1 已上线的 GET 参数，解析规则逐条照搬
（源实现：`ui/runner.py` 的 `deeplink_values` / `deeplink_region` / `deeplink_endpoint` / `parse_dataset_ref`，
测试在 `tests/test_ui_datasources.py`，测试用例一并搬过来）。rerun viewer 的「质检」按钮依赖这个契约，不能破坏。

| 用途 | 键 | 规则 |
|---|---|---|
| 数据集地址 | `dataset` / `dataset_url` / `url` | 三个键都认；**多值合并去重**，值里的逗号再拆一次，所以一次可以带多个数据集。可以是完整的 `tos://桶/前缀/数据集名`，也可以是裸名字；最后一段是数据集名，其余是根前缀 |
| 地域 | `region` | 只取第一个通过字符集校验的值（`^[a-z0-9][a-z0-9-]{1,31}$`）。只用来预选下拉，**绝不进任何请求路径** |
| 端点 | `endpoint` / `tos_endpoint` | 清洗后只取主机名，**只用于提示**：它指向的地域与本实例不同时，给一条说明，预选不受影响。绝不拿它去读数据（XSS / SSRF 面） |
| 数据来源 | `source=public` | 切到 HuggingFace 缓存桶，可再带 `dataset=名字` |

三条纪律：

1. **键出现了就必须有回应**。值为空或不合法时，在对应字段下给出常驻的红字说明，不能静默当没看见。
2. **不认识的存储桶绝不回落到默认桶**。
3. 带参进来会代填：数据来源、数据集地址、地域，以及**交付目录**（不是任务名称，也不是交付名 —— v1 同样如此）。
   交付目录的默认值：上次用过的交付根目录 → 否则借用数据集所在的存储桶 `tos://<桶>/deliveries`，
   但**要先过写探针**，只读的桶不借、留空并说明原因。用户改过的字段不再被覆盖。

v2 比 v1 多了访问密钥和 VLM 后端两个必选项，为了让深链进来仍然是「几乎不用填」：
只有一个 TOS 访问密钥 / 一个 VLM 后端时自动选中；有多个时选上次用过的；一个都没有时，
就地给「去添加」的入口，添加完回到本页，已解析的深链参数不丢。

深链带了**多个数据集**时，新建页进入批量模式：共用一套配置，一次创建 N 个任务
（`POST /tasks/batch`），交付目录各自为 `<交付根>/<数据集名>-<MMDD>`。

### 2.2 给 Agent 的反向链接

API 返回的 `links` 数组（见 `03-rest-api.md` §1）指向的就是上面这些路由，
保证 Agent 拿到 JSON 后能一键把人带到正确的页面（报告/裁决）。

### 2.3 挂载前缀

现网的 APIG 分流**不剥前缀**：质检平台和 rerun viewer 在同一个域名下，平台在 `/curation`，
请求原样带着前缀打到 Daemon。所以前端不能假设自己在根路径：

- 构建用相对资源路径（Vite `base: './'`）；
- Daemon 在返回 `index.html` 时注入 `window.__CURATOR_BASE__`，路由的 `basename`、API 前缀、SSE 地址都从它来；
- `{base}` 之下任何不是 API / 静态资源的路径都回退到 `index.html`（否则深链和刷新会 404）。

第二屏只针对已开启的模块，给出各自需要的额外输入，然后创建：

```
┌─ 模块设置 ────────────────────────────────────────┐
│ 需要补充                                            │
│ ⚠ 运动学极限   *机器人型号 [▾ franka]   [跳过该模块]   │
│ 可选设置                                            │
│ 视频-动作同步  同步曲线证据图 (•)有标注或未对齐的 ( )全部 ( )不画│

```

要点：

- 表单和顶上的「① 基本配置 ② 模块设置」步骤条用满内容区宽度（第三轮第 8 条）。
- 第二屏（第四轮）：每个模块的名称是小标题（比字段标签大一级），不再有「可选设置」这一层标题。互为替代的参数（注册表 1.10 的
  `x-choice-group`）合成一项：EEF 的「夹爪参考」先在下拉里选「观测种子」或「夹爪外观模板」，再用同一个按钮传文件，说明文字随选项变，
  换选项会丢掉已传的另一种（二选一，`required` 时必须给其一）。上传按钮先写「上传中…」，文件发完、服务端校验时写「校验中…」
  （`api/uploads.ts` 用 XMLHttpRequest 的上传事件区分两段）。「夹爪参考」的上传结果（文件名、sha256、摘要）放在整行下面、和下拉框左对齐；
  有文件还在上传或校验时，「保存为待启动」「创建并开始」不能点（悬停提示「文件还在上传或校验，通过后才能创建」），完了才能点（第四轮续三）。
- **两屏各管各的**（D38）：第一屏是基本且必填的输入，和静态稿一致；第二屏只列已开启的模块各自需要的额外输入，必填的在前（例如读不到机器人型号时，运动学极限要补型号，也可以跳过该模块），选填的在后；没有额外输入的模块不列出（2026-09-23 第二轮反馈第 16 条），一个要设置的都没有时只写一句「开启的模块都不需要额外设置，可以直接创建。」。第二屏的表单由 `GET /modules` 里各模块的 `param_schema` 生成，模块增加到十几、二十个也不用改页面。「下一步」前校验第一屏的必填项，「保存为待启动」「创建并开始」前校验第二屏的；两屏之间来回切换不丢已填的内容。编辑待启动任务、复制为新任务同样是这两屏，内容预填。
- **必填项一律红色 `*`，提交前本地校验 + 提交后服务端校验双保险**（需求硬要求）。
- 预检自动触发，不需要用户点「检测」按钮；失败时就地给原因，不弹全局报错。读不到机器人型号时写「未读到机器人型号（数据集没有声明
  robot_type），请补充型号」，不再带「或跳过该模块」（第二屏本来就有「跳过该模块」按钮；添加数据集时没有这个动作，第四轮续）。预检结果里命中数据集语义档案时写一行，没命中不写；
  不再放「未通过预检的模块会在「质检范围」里置灰…」的说明（第四轮）。质检范围里 EEF–视频一致性的卡片不提示要上传的文件
  （trajectory.json、夹爪参考都在第二屏要，卡片不标橙）。
- 交付目录失焦时做一次**真实写探针**（v1 已有此行为，保留）：写不进去当场说，
  不要等任务跑到最后一步才失败。
- **访问密钥下拉**（第三轮第 7、12 条）：验证通过的排前面，其次未验证的（写「（未验证）」），验证失败的列在最后且不能选。
  交付目录的「地域」「访问密钥」两个下拉，第一项固定写「（同数据集）」（值为空，跟随数据集），后面是去掉数据集那一项之后的其余选项；
  当前值恰好等于数据集那一项时仍列出，免得下拉里显示裸值。
- **数据来源**：「HuggingFace 缓存桶」只在站点配置了公共桶时出现；选它之后地址和地域由站点配置填好并置灰，
  只剩数据集下拉，访问密钥不需要（匿名直读）。交付目录的地域和访问密钥这时留空、必须自己选：没有「（同数据集）」，
  也不从上一次任务带默认值，空着过不了「下一步」（第四轮续六）。
- 底栏的「将质检 N 条 episode，开启 M 个模块」在预检出条数之后才出现（第四轮续六）。它是只读的，绝不会被当成交付目录。
  「本地挂载路径」默认不出现，站点开启后才有，带 experimental 标记。
  数据集可以从「数据集」页已添加的里面选，地址、地域、访问密钥和上次的预检结果一并带出；直接填地址的，预检通过后自动登记为数据集，记下指纹（D36）。
- **Episode 选择**三种方式：全部、前 N 条（v1 的「只跑前 N 条」，抽检常用）、自选。
  自选里预览网格和文本表达式互相同步；表达式由后端校验，前端不自己解析。
  预览是新能力（v1 只有文本框）：首帧由浏览器从视频里取，视口懒加载，接口见 03 篇 §10。
  数据集很大时网格只是辅助，表达式才是主路径。
- **mcap 与 Lance 数据集**（D44）：预检结果写「mcap · N 条 episode · M 路相机」（mcap 的时间轴取动作 topic 的 `log_time`，
  没有帧率）或「Lance（LeRobot v3 元数据） · …」，下面一行说明预检读了什么（mcap 只读每个文件的摘要区，Lance 只读 `meta/`）。
  EEF–视频一致性和它的复核对这两种格式标灰（只读 LeRobot 的视频）。预览网格没有首帧（视频在文件或表里，浏览器取不到），
  格子里只有下标、时长和任务文本；mcap 的任务文本只在 `/task` topic 里的，写「任务文本在 mcap 文件里，质检时读取」。
- **质检范围**的三个预设对应 v1 的「完整 / 快速 / 自选」。快速质检只勾不调模型的六项，秒级出报告，
  此时模型配置区整块隐藏、不再必填。
- 模块区的三态严格按 `availability` 渲染，标灰原因走「详细信息」弹窗，不截断成 tooltip 里的半句话。
  模块清单、中文名、可调参数全部来自 `GET /modules`。
- **思考强度**默认「模型默认」（请求里不带该字段）。下拉只列所选模型的有效档位（08 篇 §4.1）。下面不再放解释「模型默认」的小字（第四轮）。
- **高级设置里的并发是上限，不是设定值**（D31）：留空就是不限，由后端按模型并行度和节点规格决定；
  填了，后端不会超过它。执行计划本身不开放。版式（第四轮）：模型调用重试次数上限、超时对冲、CPU 并发上限、VLM 并行度上限四项一行，
  各类调用超时一行，「导出交付数据集」「预生成裁决用的视频片段」两个开关一行、开关紧挨着文字；超时对冲不再附「到时没返回就补发一次」，
  并且和同一行的另外三项一样是下拉框（「开启」「关闭」，第四轮续三）。
  超时对冲与重试不是一回事（04 篇 §6）：对冲是带图请求到了超时线还没回来时再并行补发一发、先到先用，第一发不取消，压的是长尾延迟；
  重试是一次调用失败（超时、连接错、5xx、429）之后隔 1s / 2s / 4s 再来，补的是失败。对冲默认开，与 v1 的线上形态一致；
  模型服务过载时关掉它可以少一半的补发请求。
- **点「创建并开始」时要过三项检查**（D30）：输入能读、交付目录能写、模型能调通。
  哪一项不过就在对应字段下说明原因，任务不会开始。访问密钥在管理页上标着「未验证」不影响在这里选它，
  能不能用以这三项检查为准。检查进行时按钮保持加载状态，不另写「正在做开始前检查…」（第 12 条），
  底栏也不再写「开始前会检查：数据集能读、交付目录能写」（第三轮第 13 条），提交过程中也不写「正在创建任务…」
  「正在登记数据集…」「正在确认预检结果…」（第四轮），只有按钮转圈；
  「高级设置」旁不放说明文字，预设写「快速质检」，Episode 选择的第一项写「全部」（条数在「已选 N / M 条」里）（第 15 条）。
- **开始时核对数据集指纹**（D37）：「创建并开始」和待启动任务的「启动」都会先把数据集当前的 meta 指纹和全量文件清单指纹，与添加时（或最近一次预检时）记下的比。一致就沿用已有的预检结果；不一致就弹框，说明变了什么（meta 有没有变、新增 / 删除 / 改动了多少文件、上次预检是什么时候），按钮是「取消」「重新预检」。确认后重新预检：结果与任务配置相容（所选模块仍可用、自选的 episode 仍在范围内、需要补充的输入都有）就接着开始；不相容就回到编辑页，标出要改的地方。
- 「保存为待启动」建一个 `created` 状态的任务，之后还能回到这个表单改任何字段；
  **一旦开始，只能改任务名称和备注**，想换数据、模块、模型或参数就「复制为新任务」——
  它也是打开这个表单，用原任务的配置预填（人工裁决不会带过去）。

## 4. 任务列表与任务详情

### 4.1 任务列表

- 表格列：任务名称、状态、数据集、质检模块、进度、通过率 / 待裁决徽标（已完成的）、
  Token、创建时间、操作。页头不写说明文字（第四轮续）。每行最多两行（第四轮续六）：名称列只放名称（过长省略、悬停看全文）和 ID，
  「待裁决 N」「交付待重新导出」放在状态标签旁边；1600 宽下整表放得下。
- **进度列**（2026-09-23 第二轮反馈第 20 条）：未结束的任务显示两行，第一行是当前档（合并后的名字，见 §4.2）、进度条和「已完成 / 总数」，
  第二行是整个任务的总进度百分比：没跳过的档每档权重相同，已完成的算满，当前档按它的进度条算。不写剩余时间。
- **质检模块列只放摘要**：模块以后会有十几、二十个，不能全摆出来。单元格一行「7 项」，有需要注意的才追加红色「1 项错误」或灰色「1 项未运行」；下面一行小字是预设名（完整质检 / 快速质检 / 自选）。悬停弹出完整清单：按档分组，每个模块一个状态点，有问题的排在前面，模块多了浮层可滚动。完整的逐模块状态在任务详情的模块表里。
- **页码分页**：页码 + 每页条数（10 / 20 / 50 / 100）+ 总数，与火山控制台的表格一致（D21）。
- 所有表格里，单元格开头的文字链接（「操作」列的「查看报告」「编辑」「可视化」等）从列起点开始、和表头文字对齐，
  不再被按钮的内边距往里推（第四轮续四，`styles.css` 里对表格单元格统一处理）。
  顶部按状态、按质检模块筛选（多选，只看包含这些模块的任务），按名称搜索。
- 操作随状态变化：待启动 → 启动 / 编辑 / 删除；运行中 → 暂停 / 停止；已暂停 → 恢复 / 停止；
  错误 → 重试；已停止 / 失败 → 继续运行；终态一律有 查看报告 / 复制为新任务 / 删除 / 清理交付产物。
  有结果的任务（有报告概览或结果版本）「更多」里常驻「人工裁决」，有待裁条目时写「人工裁决（N）」（D47）。
- 「重试」把出错的条目都补回来之后，这一行的状态从「错误」变为「已完成」；曾经出过错这件事在任务详情的时间线里看。
  「错误」标签是红色（和「失败」一样，第四轮续五）；报告里模块小节的「错误」同样用红色。
- 子任务（重试、继续运行、执行裁决、重新导出）运行期间，这一行的状态显示「运行中」，进度列写「子任务运行中」，下面留着它可能替换的结果；

- **删除**默认只删平台里的任务记录，TOS 上的数据不动，30 天内可在「已删除」筛选里恢复。
  确认框里有一个默认不勾的「同时清理交付产物」（只在任务写过批次目录时出现，2026-09-23 第二轮反馈第 19 条）：
  勾上后显示将被清掉的完整路径 `<交付目录>/<run_id>/`，确定时先清理、清理开始了才删记录；清理没能开始就什么都不删，并说明原因。
  这些规则只在这里写，确认框里只放路径，不再附说明文字（第四轮）。
  **清理交付产物**仍是单独的动作：弹窗里列出将被清掉的完整路径（体积在清理开始后报告），要求手动输入任务名称确认。
- 实时性：列表里有非终态任务、或有子任务在运行的任务时每 5s 轮询一次，否则不轮询（子任务结束后这一行随下一次轮询翻到重算后的终态）。不为列表单独做全局 SSE。

### 4.2 任务详情

- 顶部：状态标签 + 操作按钮。按钮的禁用状态由 `state` 决定，非法操作前端就不给点（后端仍会校验）。
  系统暂停（升级、重启造成的）同样显示「已暂停」，旁边一个图标，悬停提示「系统将自动恢复」，和用户暂停区分开。
  子任务运行期间状态标签写「运行中 · 重试 #2」这样的子任务名，子任务结束后回到重算后的终态（D46）；
  子任务的实时事件（带 `subtask_id` 的 `state` / `done`）只更新子任务，不覆盖任务自身的状态。
- 有结果的任务在页头常驻「人工裁决」（D47）：有待裁条目时写「人工裁决（N）」并用主色；没有待裁条目时是普通按钮，只剩可复议条目时也能进。
  它不再重复出现在「更多」里。主操作是「查看报告」时（已完成、错误），「查看报告」排第一个、用主色，「人工裁决」跟在它后面
  （第三轮第 14 条）；主操作是别的（继续运行等）时，「人工裁决」有待裁条目才用主色，这时原主操作降为次按钮。
- **分档进度**：每一档一根进度条，带「已完成 / 总数」和耗时，不显示预计时间（2026-09-23 第二轮反馈第 20 条）。
  「终判」「报告」合并成一根「报告生成」，「导出」「交付核验」合并成一根「交付」（第 11 条；`lib/taskView.ts` 的 `groupStages()`：
  合并后的状态按 失败 > 进行中 > 有出错条目，其余成员全部等待中为等待中、全部完成为已完成、部分完成为进行中，跳过的不计；
  条数和耗时相加，进度条对没跳过的成员等权，所以只会往前走）。概览等别的页面显示档名时用 `progressStageLabel()`。
  流式漏斗的三层（数值 / 帧 / VLM）画成三张并排的小卡片：按宽度自动分列、每张至少 200 px，一行放得下就一行，
  卡片里的计数、单条耗时不折行（第三轮第 2 条）。「Token 消耗」明细折叠的展开箭头与标题文字留出间距（第 3 条）。
- **Episode 流水线**（流式执行的任务）：最近 30 条 episode 的逐档结果，运行中每 3s 刷新。刷新时表格原样留着，只在卡片右上角
  一个固定的位置转一个小图标（第四轮：以前查询键一变就把整张表换成转圈，页面上下跳）；点开某一条的即时结果同样如此。
  日志页签的档筛选和执行计划仍用原始档名，与命令行输出一致。
  子任务运行期间换成该子任务的分档进度（`GET /tasks/{id}/subtasks` 里它的 `progress`），标题旁标明「子任务 · 重试 #2」。
  进度条从 50/50 变成 49/49 是正常的 —— 上一档拦下了一条，旁边要有一句话说明。
- 模块表：每行一个模块，状态、耗时、判决摘要、出错条数；有出错条目或模块失败时给「重试」。
- **Token 消耗卡片**：与分档进度并排、等高（窗口窄于 1100 px 时上下排）。上面是输入 / 输出 / 思维链 / 缓存命中 / 请求数五个总数，
  下面是默认展开的「明细」折叠（2026-09-23 第二轮反馈第 13 条，同静态稿）：按模块 / 按子任务切换，列为 模块（或 主流程 / 子任务）、
  请求、输入、输出、思维链、缓存命中，末行加粗「合计」；「重试花掉的也算在合计里…」的说明放在折叠里。
  只加实际调用账（01 §2.6），不显示金额（D12）。
- **执行时间线**：主流程与每一次子任务（重试、继续运行、执行裁决、重新导出）的起止、结果，

  说明文字截成两行，悬停看全文。
- 模块表里出错的条目单独计数（「2 条待补跑」），点开看是哪几条、错在哪一步。
- **日志**页签：按档筛选，默认跟随最新；历史日志往上翻是懒加载。日志是命令行原文，保持英文，系统事件也不翻译。
- **执行计划**：只读展示 planner 生成的计划（档、并发、闸门），折叠在「更多信息」里。planner 写在 plan.json 里的闸门名、
  合并方式、上限来源和估算说明是英文，页面上都换成中文（`lib/planText.ts`：打分 / 逐机位复核 / 取证仲裁 / 护栏打标 / 打标 / 归纳 /

### 4.3 概览（D36；2026-09-23 按需求方第 8 条改版，F6.1）

默认页，回答两件事：现在在跑什么，一段时间里跑了多少。只有两张并排、等高的卡片（原来的「待处理」「数据集」两块去掉了）：

  四个数字排成一行、格子收紧一些（第四轮续四；窄于 600 px 时两两一行）。

  切换时间范围时先留着上一段的数字，取回新数据后再换。

### 4.4 数据集（D36）

- 页头不写说明文字（第四轮续二）。每行一行（第四轮续六）：名称、地址、机器人型号、最近一次质检的任务名放不下时用省略号，悬停显示全文
  （`components/OneLine.tsx`，截断了才有提示）；最近一次质检的任务名和状态标签并排。列宽固定，窗口窄时整表横向滚动。
- **列表**：名称、来源（私有 TOS / HuggingFace 缓存桶）、地址、格式（LeRobot v2 / v3 / mcap / Lance / 不支持，D44）、episode 数、
  机器人型号、指纹状态（一致 / 有变化，待重新预检 / 未检查）、最近一次质检（任务名 + 状态）、添加时间、
  操作（可视化 / 新建任务 / 删除，删除为红色；「重新检查」「重新预检」在详情页，2026-09-23 第二轮反馈第 22 条）。
  页码分页，按名称搜索，按格式和指纹状态筛选。
- **可视化**：在新标签页打开同域的 ReRun web viewer，直接加载这个数据集（D48）。viewer 在控制台挂载前缀的上一级（`/curation` → `/`），
  地址是 `<同域>/<上一级>/?url=<值>`，值是 URL 编码后的 `tos://存储桶/前缀/数据集名/`，有地域时在 tos 地址后面接 `?region=<地域>`
  （ReRun 解析 `tos://…/?region=cn-beijing`）；数据集名就是地址的最后一段，访问密钥由 ReRun 自己的部署配置提供，这里不传。
  HuggingFace 缓存桶的数据集一样处理；本地挂载的数据集按钮置灰，提示「本地挂载的数据集不支持可视化」。
  控制台挂在根路径时没有上一级，链接指向同域根路径。详情页页头也有「可视化」。实现在 `src/lib/rerun.ts`。
- **添加数据集**：右侧抽屉，填来源、地址、地域、访问密钥（缓存桶不需要）→ 自动预检 → 通过后保存，
  记下 meta 指纹和全量文件清单指纹。在新建任务页直接填地址的，预检通过后也会自动登记。
  同一个来源 + 地址 + 地域只登记一次。
- **详情**：预检结果（格式、条数、相机、帧率、机器人型号、模块可用性）、指纹与变化记录
  （每次检查的时间、结果、变了什么）、在这个数据集上跑过的任务；「新建质检任务」用它预填新建页。
  数据集自己的预检不选 VLM 后端，所以要模型的模块在预检里是 `vlm_backend_missing`；详情页不把它当「需要补充」，
  而是直接看 VLM 后端：只要有一个验证通过、带能看图的模型的后端就写「可用」，一个都没有才写「需要补充 · 没有可用的 VLM 后端」
  （第三轮第 11 条，`lib/preflight.ts` 的 `withVlmBackends()`）。模块列宽 240 px，最长的模块名不折行。
- **重新检查**只重算指纹、和记下的比，不动任何任务；有变化就标出来，并给「重新预检」。
  开始任务时的核对是同一套比较（D37，见 §3）。
- **删除**只删平台里的登记，不动 TOS 上的数据；有非终态任务在用时不能删。

## 5. 质检报告页

2026-09-23 按需求方第二轮意见（第 1、2、14、18 条，F6.2）改版：报告只放统计和图，逐条的内容挪进单独的页签。

- **三个页签**：「报告」「Episode 明细」「性能剖析」，地址分别是不带 hash、`#episodes`、`#perf`。

  地址可以直接分享；以前指向逐条抽屉的 `?ep=N` 链接直接打开 Episode 明细。切换 `?rev` / `?ep` 不换页签。

  「人工裁决（N）」并用主色，历史版本置灰并提示「历史版本只读」。页头不再写「小节和本次开启的 N 个模块一一对应」。

**「报告」页签**

- 开头两块：质检总览（输入 = 判废 + 交付 + 待补跑，判废原因分布，通过率，耗时，Token）和数据包完整性。

  按执行时间线算这一版背后的运行：「16 分 58 秒 + 7 分 00 秒 / 主流程 + 重试 #1」。
  有源文件缺失被跳过的条目时（D40），总览写「另有 N 条缺源文件，未参与质检」，完整性一块列出是哪几条、各缺什么文件；
  它们不在三份清单里，也没有「重试」入口（源数据已固化，补齐文件后另建任务）。
- **数据包完整性**全中文、横向排版（静态稿 `.desc` 的样子，一行三组「名称 值」）：格式（LeRobot v3（结构校验通过）/ 不支持的原因）、
  Episode（数据集多少条，本次质检哪些）、相机（几路、分别叫什么）、帧率、机器人型号（没读到时注明运动学极限未运行）、
  语义档案（命中哪个档案、按什么匹配）、任务标注（多少条有 / 没有，没有的由模型补描述）、源文件清单（对象数、体积、指纹，启动时固化）、
  结构校验、预检提示（CLI 的英文提示翻成中文，认不出的注明「命令行原文」）。不出现英文键名和 JSON；报告里有而页面不认识的键也照样列出，按可读方式显示。
  mcap / Lance 源（D44）的完整性一块多一行「数据包（mcap / Lance）」：交付形态（Lance 写明原格式交付未做）和 v1 的数据包体检（型号、时间轴、任务文本）。
- **本次质检范围**：模块、判决方式、状态、一句话说明（「判废 1 条」「平均分 0.84」「错位判废 0 条，已标注 3 条」「6 个技能族，标注分歧 5 条」），
  点名称跳到对应小节（折叠着的小节会先展开）；右上角「全部折叠 / 全部展开」。
- **模块小节与勾选模块一一对应**，顺序按 `report.json` 的 `modules` 数组。每个小节是一行关键数字加一到三张图，
  数据来自 `summary` 里「画图就能用」的汇总（06 篇 §6.2 的汇总键）：**只放统计，不列具体的 episode，不出现 JSON 原文**。
  八个模块和两个 EEF 模块各有专用视图（`SECTION_VIEWS`）：

  | 模块 | 关键数字 | 图 |
  |---|---|---|
  | 时间戳检查 | 不合格、乱序 / 跳变 / 残段 / 抖动、检查条数、总时长、时长中位数、最短 / 最长 | 不合格原因、时长分布 |

  | 技能画像 | 覆盖条数、技能族、子技能、样本偏少的族、标注分歧（高置信 / 人工复核）、看法不稳、分组依据 | 技能分布、子技能分布 |

  | EEF–视频一致性 · VLM 复核 | 完整复核、未完成、未复核、待人工看、与 CPU 冲突、复核窗口、模型请求 | 复核状态、复核结论、窗口失败原因 |

  所有模块另外可能有「弃权原因」和「出错停在哪一步」两张图。注册表里还没有专用视图的模块用默认视图：判决分布一张图，
  标量成关键数字，`[{name, count}]` 数组和计数字典成柱状图，其余按中文标签可读地列出 —— 加模块不需要改前端。
  改版前生成的报告只有计数和少数几个数，小节照样显示已有的内容，并注明「这份报告生成于统计图上线之前」。
  版式（第三轮第 4、5 条）：指标卡每张至少 176 px，数值不折行，一列放不下的数值（如「16 分 58 秒 + 7 分 00 秒」）自动占两列、
  不截断（`components/StatCell.tsx`）；图按宽度自动分列（每列至少 360 px），图表左对齐不留大片空白，横向条形图按条数定高，
  「逐相机典型滞后」占两列。
  卡片右上角不放说明文字（第四轮）：质检总览、数据包完整性、本次质检范围和性能剖析的两张卡片只留按钮。
- **折叠**：每个小节标题栏最右边一个「收起 / 展开」，默认展开；折叠状态按浏览器记住（`lib/prefs`，按模块 id），
  下次打开任何报告都一样。
- 有待裁决条目的小节，右上角「去裁决（N）」跳 `/tasks/:id/adjudication?source=<module>`；可复议的是「可复议（N）」。
- 失败的小节显示错误 + 「重试此模块」。
- 底部的「明细表」和右侧的逐条抽屉都已去掉（需求方：放在报告底部体验不好）；明细表接口（03 篇 §6）仍在，给 Agent 和导出用。

**「Episode 明细」页签**（v1「轨迹」页的对应物）

- 顶部一行：下拉搜索框（按 episode 编号模糊查询，输入 `12`、`ep12`、`ep 12` 都能找到 ep 12；每个选项写「ep 12」，
  带清单标签（通过 / 拒绝 / 待补跑）和「待裁」标记），筛选「全部 / 通过 / 拒绝 / 待补跑 / 待裁决」（带条数），
  「上一条 / 下一条」在筛选后的顺序里走。没有 `?ep` 时显示筛选后的第一条。数据来自 `GET /tasks/{id}/episodes`（03 篇 §6）。
- 下面一张卡片接一张：
  1. **判决概要**：所在清单与「待裁」、判定原因、待人工确认的问题（裁决页会问的——模块登记了这类问题行，或可复议模块的判废——每个来源模块一个「去裁决」，
     被拒复议的去复议页签；别的模块的弃权只列出、不给入口；历史版本置灰）、
     任务文本与来源（原始标注 / 自产描述 / 人工改标）。
  2. **各机位视频**：同步播放，见下。
  3. **证据帧**。
  4. **每个模块一块**，顺序同报告小节：判决标签、分数、耗时、出错原因，以及这一条在该模块下的读数，全中文：
     时间戳（时长、帧数、帧间隔、异常位置）；运动学（越限明细：类型、关节、帧、实测值、极限）；
     运动质量（各子项得分与计分方式、不适用的原因，卡死与空闲）；视觉质量（逐相机的总分、清晰度、曝光、完整性、冻结帧、状态）；
     同步（结论标签、逐相机滞后 / 峰值 / 可信 / 诊断，加同步曲线：左边画面运动与机械臂运动随时间的曲线，右边互相关曲线、容差绿带与读数点，
     数据来自 `GET /tasks/{id}/episodes/{index}/sync-curves`，没保存曲线时写明原因）；
     任务成败（判定链：打分层 → 逐机位复核 → 判废护栏 → 取证仲裁 → 结论，没走到的层写「未触发」；理由；意图取自哪种文本；打分层完成度曲线）；
     精确去重（无重复 / 与 ep N 字节级完全重复，ep N 可点）；技能画像（技能族、子技能、模型描述、分组依据）；EEF（逐相机分项状态）。
     没有专用块的模块按中文标签列出读数；这一条没走到的模块写「未进入这一档（前面已判废或待补跑）」。
- **同步播放**（需求方第 14 条；报告的 Episode 明细和人工裁决卡片用同一个控制器）：
  - 不自动播放：打开页面、切换 episode 都不会播放，也不签名；只有点「同时播放」才给所有机位签名。
  - 起播前每一路都要缓冲好（可以播放，且播放点之后至少缓冲 2 秒，或已缓冲到这一条的结尾），并对齐到这一条里的同一时刻
    （LeRobot v3 的一个文件拼了多条，时间按各自的 `from_ts` 换算），然后一起开始。
  - 播放中任一路缓冲不足（`waiting`、`stalled` 且余量不足、缓冲余量低于 0.5 秒、出错重签）就全部暂停，旁边显示「缓冲中…」；
    各路都缓冲好后一起继续。各路相差超过 0.2 秒时对齐到第一路。
  - 在任一路上用自带控件暂停、播放、拖动，其它路跟着做；按钮变成「停止同步」，点它全部暂停、各路恢复独立。
  - 地址过期或 403 照旧自动重签；一路彻底打不开时其余几路照常同步播放。
**「性能剖析」页签**：模型服务与容器配额、五类调用的延迟分布、有效并发度、各阶段耗时对比（原叫「各阶段墙钟占比」，
  表格里的「墙钟」列也改叫「耗时」，第四轮续二）、重试与合并的统计；可在「全部 / 仅主流程 / 某次子任务」之间切换。

## 6. 人工裁决页

入口常驻（D47）：任务一旦有结果，详情页头、报告页头、任务列表的「更多」里都有「人工裁决」，有待裁条目时带数量；
待裁决页签一条都没有时只写「没有符合筛选条件的条目」（按默认的「待裁」筛选；选「全部」时是「这个任务没有要人工裁决的条目」），
不再提示去被拒复议，也不给链接；被拒复议页签没有条目时同样写「没有符合筛选条件的条目」（第四轮续二）。页面顶部不放
「裁决只属于这个任务…」的说明。

统一入口，**以 episode 为索引**：一条 episode 一张卡片，不按模块分组。卡片上写明「来源」——是哪个或哪几个模块的输出要人来判，每个问题前再注明来自哪个模块、要判什么（2026-09-21 静态稿评审定；v1 在 2026-08-16 也改成了只按 episode 合并）：

```
筛选：来源模块 [全部 ▾] 问题类型 [全部 ▾] 状态 [仅待裁决 ▾]  已裁 3 条 · 待裁 7 条 · 3 条尚未应用
┌ episode 29 ─────────── 来源：技能画像、任务成败判定 ┐
│ [三路机位视频]  [同时播放]   [证据帧]                  │
│ ① 来源：技能画像 · 标注分歧                           │
│    原始标注：Put the orange thing in the can         │
│    画面描述：pour rice into the green bowl            │
│    (采纳新标注) (维持原标注) (拿不准)  [自行改写标注]   │
│ ② 来源：任务成败判定 · 证据不足，弃权                  │
│    (判成功) (判失败) (拿不准)                         │
│                                   [其它原因，整条弃用] │
└────────────────────────────────────────────────────┘
                                          [执行裁决]
```

- 同一条 episode 的多个问题放在**一张卡片**里，视频只看一次（v1 如此）。
- 筛选：来源模块（多选）、问题类型、状态。从报告页的「去裁决（N）」进来时按来源模块预先筛好（`?source=`）。
  「来源模块」放在两个页签各自的筛选行里（第三轮第 15 条）：待裁决页签的选项是 `produces_adjudication` 的模块，
  被拒复议页签的是 `appealable` 的模块；切换页签时清掉来源筛选（两边的模块不同）。
- 每点一下就保存（只记录，可反复改）；「执行裁决」才建子任务真跑。两者分开是刻意的。
  页面顶部常驻一条「N 条裁决尚未应用」的提示，直到执行。
- 「执行裁决」先弹确认框，列出这次要应用几条、其中几条改了标要重判任务成败。有改标重判时说明口径（D39）：
  默认与旧版一致，只跑多视角打分和逐机位复核两层；另给一个选项「按首轮的完整流程重判」（多了判废护栏和取证仲裁，
  判得更全，但同样的裁决可能得出和旧版不同的结论）。选择随请求体的 `relabel_rerun` 提交，执行时间线上的这次子任务标明用了哪种。
  人已判了成功/失败的改标条目不重判，确认框里也写明。
- 裁决只属于本任务，不会带到别的任务，也不会从别的任务带过来（06 篇 §5.3）。
- 「被拒复议」是单独的页签（静态稿里叫「任务失败复议」，叫法随文案一起改）：列出归因于可复议模块的拒绝 ——
  现在是只归因于任务成败判定的，和去重拒掉的（D42）。去重的卡片写明「与 episode X 字节级完全重复」，
  并排放这两条的视频；物理与结构硬门、软分拒绝是终局，页面上要解释「为什么有的被拒条目不在这里」。
  按钮是「恢复为可用 / 维持拒绝」，沿用 v1 的叫法。复议是可选的，不计入「待裁」。
  页签顶部不再放「这里列出可复议模块拒掉的条目……」的说明（第三轮第 16 条），「为什么有的被拒条目不在这里」的折叠保留。
- 只有标注分歧的卡片上，选了「采纳新标注 / 自行改写标注」之后出现选填的成败结论（v1 如此，由目录的 `follow_ups` 表达）：
  答了，机器直接采信、不再重判；留空，执行时按新标注重判。改掉标注的判断，这个回答随之作废。
- 复核种类来自注册表的复核目录（D43）：已知的三种有专用视图，没有专用视图的种类按目录通用渲染
  （标题、理由、每个判断一个按钮），来源模块的筛选项取注册表里 `produces_adjudication` 的模块。
- 视频来源按 片段 → 交付数据集 → 源数据集 的顺序取（03 篇 §7），经 **TOS 预签名 URL 直连**，
  403/过期时自动重签重试。卡片上的「同时播放」与报告 Episode 明细是同一套同步规则（§5）：不自动播放，
  各路缓冲好才一起开始，任一路缓冲不足全部暂停。
- 队列用游标取（每次 200 条，契约上限），页面在后台取全；卡片分页显示，默认每页 10 张，可切 10 / 20 / 50
  （第三轮第 10 条，`pages/adjudication/paging.tsx`）；换筛选回到第 1 页，底部仍写「已加载全部 N 条」，后面几批没取到时给「重试」。

## 7. 系统和资源配置页

仿 VKE 的保密字典 / 配置项页面：列表 + 右侧抽屉表单。两类资源：

1. **TOS 访问密钥**：名称 + Access Key ID + Secret Access Key + 地域。保存时只验身份（08 篇 §4）；
   对具体存储桶能不能读、能不能写，在新建任务时验（交付目录失焦的写探针、开始前的三项检查）。
   这些规则只写在文档里：页头不放说明，访问密钥页签和新建访问密钥的抽屉也不放「保存时只验身份…」（第四轮续二）。
   访问密钥表每行一行（第四轮续六）：验证失败或未验证的原因跟在标签后面、截断显示、悬停看全文；「被引用」写「N 个任务」，
   有未结束的才加「 · 其中 M 个未结束」，不再写「都已结束」。
2. **VLM 后端**（方舟或自定义，流程相同）：名称 + endpoint + API Key（自定义端点可不填）。
   - 保存后**试着拉一次模型列表**（`GET {endpoint}/models`）。拉得出来就列出来；
     拉不出来不报错，直接让用户手填 Model ID 或推理接入点 ID（`ep-…`）。
   - 模型表格上方一个框，按能不能拉到列表分两种（2026-09-23 第二轮反馈第 9 条）：拉到了列表的后端，是只做查询的模糊筛选框
     （字母按顺序出现即可，列表随输入更新，不能添加）；拉不到的后端，是「输入模型 ID」+「添加」
     （添加前发一次最小请求验证，列表里已有的名字不重复添加）。每页 10 个。
     操作列里「设为默认」和「移除」挨在一起，默认模型是「默认」标签 +「取消默认」+「移除」。
     表格下面不再解释默认模型的规则（第四轮续）；认不出推理接入点背后的模型时只写「思考强度列出全部 7 档，实际生效的档位以服务端映射为准。」
     不要求用户提供方舟的管理 AK/SK，平台也不维护内置的模型清单。
   - 每个模型可配：思考强度（默认「模型默认」）、并行度 N（默认 64）。

列表页只展示非敏感信息（地域、endpoint、模型数）和**验证状态**：已验证 / 未验证 / 验证失败（附原因），
**永不回显密钥**；编辑时密钥字段留空表示不修改。
没验证过、验证失败的都可以保存（D30）—— 用户可能先填、后开通权限。但保存成功不等于能跑任务：
任务开始前的三项检查（§3）才是关口。

## 8. 术语表（对齐火山控制台）

需求要求术语和使用习惯对齐现有火山产品。界面文案、报错、文档统一用右边一列：

| 地区 | **地域** | Region。火山全系产品的叫法 |

## 9. 工程约定

- **所有表单必填项红 `*` + 校验**（需求硬要求，写进 lint 检查清单）。
- 错误展示三级：字段级（表单内联）、操作级（Message）、页面级（结果页），不混用。
- 长任务不阻塞 UI：所有写操作立即返回，靠 SSE/轮询更新。
- **SSE 不可用时自动降级为 5s 轮询**，用户无感。
- **Lazy Loading 用在重内容上**：episode 预览网格、报告小节的图（滚到才画）、视频（点了才取签名地址，
  「同时播放」才一起签）、同步曲线图、日志、裁决队列。任务列表本身是页码分页。
- 所有面向用户的文案先过 [humanizer-zh](https://github.com/op7418/humanizer-zh) 的规则过一遍，
  具体做法：文案集中在 `src/locales/zh.ts` 一个文件里，提交前人工过一遍规则表；
  不引入运行时依赖。
- 时间一律显示本地时区 + 相对时间（「3 分钟前」），hover 出绝对时间。
- 不写死任何绝对路径，一切从 `window.__CURATOR_BASE__` 拼（§2.3）。
