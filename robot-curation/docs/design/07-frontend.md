# 07 前端设计

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 团队通用 |
| 组件库 | **Arco Design**（`@arco-design/web-react`） | 火山系设计语言，对齐控制台最省力 |
| 路由 | React Router 6 | 深链需要真实 URL |
| 数据层 | TanStack Query | 轮询、缓存失效、乐观更新都是现成的 |
| 构建 | Vite | 产物是纯静态，交给 Daemon serve |
| 图表 | ECharts（Arco 生态） | 技能分布、延迟分布、同步曲线、通过率 |
| 语言 | 界面中文，仅亮色主题 | 需求明确 |

**前端零业务状态**（D17）：所有状态读自 API，
本地只存 UI 偏好（列宽、折叠、每页条数、上次选的筛选项）。刷新页面不丢任何东西。

## 2. 页面与路由

下面的路由都挂在部署前缀 `{base}` 之下（§2.3）。

| 路由 | 页面 | 说明 |
|---|---|---|
| `/tasks` | 任务列表 | 默认页，页码分页 |
| `/tasks/new` | 新建任务 | 含预检、模块选择、Episode 选择、VLM 配置；也承担「编辑待启动任务」和「复制为新任务」 |
| `/tasks/:id` | 任务详情 | 状态、分档进度、模块表、Token、子任务、日志、报告概览 |
| `/tasks/:id/report` | 质检报告 | 与模块一一对应的小节 + 逐条下钻 + 性能剖析 |
| `/tasks/:id/adjudication` | 人工裁决 | 统一入口，按来源模块分组 |
| `/credentials` | 密钥与资源管理 | TOS 访问密钥、方舟后端、自定义端点 |
| `/`（带深链参数） | — | v1 的旧入口，302 到 `/tasks/new` 并原样带上参数 |

### 2.1 深链（契约不变）

`/tasks/new` 必须接受 v1 已上线的 GET 参数，解析规则逐条照搬
（源实现：`ui/runner.py` 的 `deeplink_values` / `deeplink_region` / `deeplink_endpoint` / `parse_dataset_ref`，
测试在 `tests/test_ui_datasources.py`，测试用例一并搬过来）。rerun viewer 的「质检」按钮依赖这个契约，不能破坏。

| 用途 | 键 | 规则 |
|---|---|---|
| 数据集地址 | `dataset` / `dataset_url` / `url` | 三个键都认；**多值合并去重**，值里的逗号再拆一次，所以一次可以带多个数据集。可以是完整的 `tos://桶/前缀/数据集名`，也可以是裸名字；最后一段是数据集名，其余是根前缀 |
| 地域 | `region` | 只取第一个通过字符集校验的值（`^[a-z0-9][a-z0-9-]{1,31}$`）。只用来预选下拉，**绝不进任何请求路径** |
| 端点 | `endpoint` / `tos_endpoint` | 清洗后只取主机名，**只用于提示**：它指向的地域与本实例不同时，给一条说明，预选不受影响。绝不拿它去读数据（XSS / SSRF 面） |
| 数据来源 | `source=public` | 切到 HuggingFace 缓存桶，可再带 `dataset=名字` |

三条纪律：

1. **键出现了就必须有回应**。值为空或不合法时，在对应字段下给出常驻的红字说明，不能静默当没看见。
2. **不认识的存储桶绝不回落到默认桶**。
3. 带参进来会代填：数据来源、数据集地址、地域，以及**交付目录**（不是任务名称，也不是交付名 —— v1 同样如此）。
   交付目录的默认值：上次用过的交付根目录 → 否则借用数据集所在的存储桶 `tos://<桶>/deliveries`，
   但**要先过写探针**，只读的桶不借、留空并说明原因。用户改过的字段不再被覆盖。

v2 比 v1 多了访问密钥和 VLM 后端两个必选项，为了让深链进来仍然是「几乎不用填」：
只有一个 TOS 访问密钥 / 一个 VLM 后端时自动选中；有多个时选上次用过的；一个都没有时，
就地给「去添加」的入口，添加完回到本页，已解析的深链参数不丢。

深链带了**多个数据集**时，新建页进入批量模式：共用一套配置，一次创建 N 个任务
（`POST /tasks/batch`），交付目录各自为 `<交付根>/<数据集名>-<MMDD>`。

### 2.2 给 Agent 的反向链接

API 返回的 `links` 数组（见 `03-rest-api.md` §1）指向的就是上面这些路由，
保证 Agent 拿到 JSON 后能一键把人带到正确的页面（报告/裁决）。

### 2.3 挂载前缀

现网的 APIG 分流**不剥前缀**：质检平台和 rerun viewer 在同一个域名下，平台在 `/curation`，
请求原样带着前缀打到 Daemon。所以前端不能假设自己在根路径：

- 构建用相对资源路径（Vite `base: './'`）；
- Daemon 在返回 `index.html` 时注入 `window.__CURATOR_BASE__`，路由的 `basename`、API 前缀、SSE 地址都从它来；
- `{base}` 之下任何不是 API / 静态资源的路径都回退到 `index.html`（否则深链和刷新会 404）。

## 3. 新建任务页（最复杂的一页）

```
┌─ 基本信息 ────────────────────────────────────────┐
│ *任务名称                    备注（选填）            │
│ *数据来源    (•) 私有 TOS   ( ) HuggingFace 缓存桶   │
│ *数据集地址  [tos://...            ]  *地域 [▾]     │
│ *访问密钥    [▾ 从密钥管理里选]      ← 缓存桶不需要   │
│ *交付目录    [tos://...            ]  *地域 [▾]     │
│ *交付密钥    [▾ 默认同上]           (失焦即写探针)    │
└───────────────────────────────────────────────────┘

┌─ 质检范围 ────────────────────────────────────────┐
│ (•) 完整质检   ( ) 快速质检（不调用模型的六项）  ( ) 自选│
│ ☑ 时间戳检查   ☑ 视觉质量   ☑ 视频-动作同步 …        │

└───────────────────────────────────────────────────┘
┌─ 模型配置 ────────────────────────────────────────┐
│ *VLM 后端 [▾ ark-prod]  *模型 [▾]  思考强度 [▾ 模型默认]│
└───────────────────────────────────────────────────┘
┌─ 高级设置（折叠）─────────────────────────────────┐
│ 模型调用重试次数上限 [3]  超时对冲 [开]  各类调用超时 […]│
│ CPU 并发上限 [不限]      VLM 并行度上限 [不限]         │
│ ☑ 导出交付数据集      ☐ 预生成裁决用的视频片段        │
│ 执行计划与请求合并由后端自动决定，这里只能设上限。     │
└───────────────────────────────────────────────────┘
将质检 200 条 episode，开启 7 个模块   [取消] [保存为待启动] [创建并开始]
```

要点：

- **必填项一律红色 `*`，提交前本地校验 + 提交后服务端校验双保险**（需求硬要求）。
- 预检自动触发，不需要用户点「检测」按钮；失败时就地给原因，不弹全局报错。
- 交付目录失焦时做一次**真实写探针**（v1 已有此行为，保留）：写不进去当场说，
  不要等任务跑到最后一步才失败。
- **数据来源**：「HuggingFace 缓存桶」只在站点配置了公共桶时出现；选它之后地址和地域由站点配置填好并置灰，
  只剩数据集下拉，访问密钥不需要（匿名直读）。它是只读的，绝不会被当成交付目录。
  「本地挂载路径」默认不出现，站点开启后才有，带 experimental 标记。
- **Episode 选择**三种方式：全部、前 N 条（v1 的「只跑前 N 条」，抽检常用）、自选。
  自选里预览网格和文本表达式互相同步；表达式由后端校验，前端不自己解析。
  预览是新能力（v1 只有文本框）：首帧由浏览器从视频里取，视口懒加载，接口见 03 篇 §10。
  数据集很大时网格只是辅助，表达式才是主路径。
- **质检范围**的三个预设对应 v1 的「完整 / 快速 / 自选」。快速质检只勾不调模型的六项，秒级出报告，
  此时模型配置区整块隐藏、不再必填。
- 模块区的三态严格按 `availability` 渲染，标灰原因走「详细信息」弹窗，不截断成 tooltip 里的半句话。
  模块清单、中文名、可调参数全部来自 `GET /modules`。
- **思考强度**默认「模型默认」（请求里不带该字段）。下拉只列所选模型的有效档位（08 篇 §4.1）。
- **高级设置里的并发是上限，不是设定值**（D31）：留空就是不限，由后端按模型并行度和节点规格决定；
  填了，后端不会超过它。执行计划本身不开放。
- **点「创建并开始」时要过三项检查**（D30）：输入能读、交付目录能写、模型能调通。
  哪一项不过就在对应字段下说明原因，任务不会开始。访问密钥在管理页上标着「未验证」不影响在这里选它，
  能不能用以这三项检查为准。
- 「保存为待启动」建一个 `created` 状态的任务，之后还能回到这个表单改任何字段；
  **一旦开始，只能改任务名称和备注**，想换数据、模块、模型或参数就「复制为新任务」——
  它也是打开这个表单，用原任务的配置预填（人工裁决不会带过去）。

## 4. 任务列表与任务详情

### 4.1 任务列表

- 表格列：任务名称、状态、数据集、进度（运行中显示当前档和百分比）、通过率 / 待裁决徽标（已完成的）、
  Token、创建时间、操作。是否单列「质检模块」见静态稿的待确认项。
- **页码分页**：页码 + 每页条数（10 / 20 / 50 / 100）+ 总数，与火山控制台的表格一致（D21）。
  顶部按状态筛选、按名称搜索。
- 操作随状态变化：待启动 → 启动 / 编辑 / 删除；运行中 → 暂停 / 停止；已暂停 → 恢复 / 停止；
  部分错误 → 重试；已停止 / 失败 → 继续运行；终态一律有 查看报告 / 复制为新任务 / 删除 / 清理交付产物。
  已完成且有待裁决条目的，多一个「人工裁决」。
- 「重试」把出错的条目都补回来之后，这一行的状态从「部分错误」变为「已完成」；曾经出过错这件事在任务详情的时间线里看。
- **删除**只删平台里的任务记录，TOS 上的数据不动，30 天内可在「已删除」筛选里恢复。
  **清理交付产物**是另一个动作：弹窗里列出将被清掉的完整路径和体积，要求手动输入任务名称确认。
- 实时性：列表里有非终态任务时每 5s 轮询一次，全是终态就不轮询。不为列表单独做全局 SSE。

### 4.2 任务详情

- 顶部：状态标签 + 操作按钮。按钮的禁用状态由 `state` 决定，非法操作前端就不给点（后端仍会校验）。
  系统暂停（升级、重启造成的）显示为「已暂停 · 系统将自动恢复」，和用户暂停区分开。
- **分档进度**：每一档一根进度条，带耗时和预计剩余（v1 任务卡的样子）。
  进度条从 50/50 变成 49/49 是正常的 —— 上一档拦下了一条，旁边要有一句话说明。
- 模块表：每行一个模块，状态、耗时、判决摘要、出错条数；有出错条目或模块失败时给「重试」。
- **Token 消耗卡片**：输入 / 输出 / 思维链 / 缓存命中 / 请求数，按模块展开，可按子任务展开。不显示金额（D12）。
- **执行时间线**：主流程与每一次子任务（重试、继续运行、执行裁决、重新导出）的起止、结果，
  以及系统暂停与自动恢复的记录。补跑成功后任务状态会变成「已完成」，但原先哪几条出过错、什么时候补的，都在这里。
  每个节点可以打开当时那一版报告。
- 模块表里出错的条目单独计数（「2 条待补跑」），点开看是哪几条、错在哪一步。
- **日志**页签：按档筛选，默认跟随最新；历史日志往上翻是懒加载。
- **执行计划**：只读展示 planner 生成的计划（档、并发、闸门），折叠在「更多信息」里。
- **交付过期横幅**：`delivery_stale=1` 时置顶显示「判决已更新，交付数据集待重新导出」+ 按钮。
- 已完成的任务直接在本页展示报告概览（总数 / 通过 / 拒绝 / 待裁决 / 通过率），并给「查看详细报告」。

## 5. 质检报告页

- 开头两块：质检总览（输入 = 判废 + 交付 + 待补跑，判废原因分布，耗时，Token）和数据包完整性。
  有待补跑的条目时，总览上给「重试」入口，并说明这几条暂未交付。
- **模块小节与勾选模块一一对应**，顺序按 `report.json` 的 `modules` 数组；每个小节的内容见 06 篇 §6.2。
  同步曲线、卡顿时间线、技能分布这几个专用视图是 v1 已有的，按 v1 的信息量做，不是一张表格能替代的。
- 有待裁决条目的小节，右上角「去裁决（N）」跳 `/tasks/:id/adjudication?source=<module>`。
- 失败的小节显示错误 + 「重试此模块」。
- 明细表走服务端切片分页（100 行/页），排序字段限白名单。
- **逐条下钻**：任一明细表里点某条 episode，右侧抽屉展示它的判决卡、在每个模块下的读数、证据帧、
  各机位视频（可同时播放）。这是 v1「轨迹」页的对应物。
- 性能剖析独立 tab：模型服务与容器配额、五类调用的延迟分布、有效并发度、stage 墙钟占比、
  重试与合并的统计；可在「全部 / 仅主流程 / 某次子任务」之间切换。

## 6. 人工裁决页

统一入口，**按来源模块分组**，每条明确写「这是哪个模块要求人来判的、要判什么」：

```
筛选：问题类型 [全部 ▾]   状态 [仅待裁决 ▾]        已裁 3 条 · 待裁 7 条 · 3 条尚未应用
┌ episode 29 ────────────────────────────────────────┐
│ [三路机位视频]  [同时播放]   [证据帧]                  │
│ ① 来源：技能画像 · 标注分歧                           │
│    原始标注：Put the orange thing in the can         │
│    画面描述：pour rice into the green bowl            │
│    (采纳新标注) (维持原标注) (拿不准)  [自行改写标注]   │
│ ② 来源：任务成败判定 · 证据不足，弃权                  │
│    (判成功) (判失败) (拿不准)                         │
│                                   [其它原因，整条弃用] │
└────────────────────────────────────────────────────┘
                                          [执行裁决]
```

- 同一条 episode 的多个问题放在**一张卡片**里，视频只看一次（v1 如此）。
- 每点一下就保存（只记录，可反复改）；「执行裁决」才建子任务真跑。两者分开是刻意的。
  页面顶部常驻一条「N 条裁决尚未应用」的提示，直到执行。
- 裁决只属于本任务，不会带到别的任务，也不会从别的任务带过来（06 篇 §5.3）。
- 「任务失败复议」是单独的页签：只列归因于任务成败判定的拒绝，其余硬门是终局；
  页面上要解释「为什么有的被拒条目不在这里」。
- 视频来源按 片段 → 交付数据集 → 源数据集 的顺序取（03 篇 §7），经 **TOS 预签名 URL 直连**，
  403/过期时自动重签重试。
- 队列用游标分页，往下翻懒加载。

## 7. 密钥与资源管理页

仿 VKE 的保密字典 / 配置项页面：列表 + 右侧抽屉表单。两类资源：

1. **TOS 访问密钥**：名称 + Access Key ID + Secret Access Key + 地域。保存时只验身份（08 篇 §4）；
   对具体存储桶能不能读、能不能写，在新建任务时验（交付目录失焦的写探针、开始前的三项检查）。
2. **VLM 后端**（方舟或自定义，流程相同）：名称 + endpoint + API Key（自定义端点可不填）。
   - 保存后**试着拉一次模型列表**（`GET {endpoint}/models`）。拉得出来就列出来让用户勾；
     拉不出来不报错，直接让用户手填 Model ID 或推理接入点 ID（`ep-…`）。
     不要求用户提供方舟的管理 AK/SK，平台也不维护内置的模型清单。
   - 每个模型可配：思考强度（默认「模型默认」）、并行度 N（默认 64）。

列表页只展示非敏感信息（地域、endpoint、模型数）和**验证状态**：已验证 / 未验证 / 验证失败（附原因），
**永不回显密钥**；编辑时密钥字段留空表示不修改。
没验证过、验证失败的都可以保存（D30）—— 用户可能先填、后开通权限。但保存成功不等于能跑任务：
任务开始前的三项检查（§3）才是关口。

## 8. 术语表（对齐火山控制台）

需求要求术语和使用习惯对齐现有火山产品。界面文案、报错、文档统一用右边一列：

| 不要用 | 用 | 说明 |
|---|---|---|
| 地区 | **地域** | Region。火山全系产品的叫法 |
| TOS 凭证、AK/SK | **访问密钥**（Access Key ID / Secret Access Key） | 与火山「密钥管理」一致 |

## 9. 工程约定

- **所有表单必填项红 `*` + 校验**（需求硬要求，写进 lint 检查清单）。
- 错误展示三级：字段级（表单内联）、操作级（Message）、页面级（结果页），不混用。
- 长任务不阻塞 UI：所有写操作立即返回，靠 SSE/轮询更新。
- **SSE 不可用时自动降级为 5s 轮询**，用户无感。
- **Lazy Loading 用在重内容上**：episode 预览网格、报告明细表、视频（点了才取签名地址）、
  同步曲线图、日志、裁决队列。任务列表本身是页码分页。
- 所有面向用户的文案先过 [humanizer-zh](https://github.com/op7418/humanizer-zh) 的规则过一遍，
  具体做法：文案集中在 `src/locales/zh.ts` 一个文件里，提交前人工过一遍规则表；
  不引入运行时依赖。
- 时间一律显示本地时区 + 相对时间（「3 分钟前」），hover 出绝对时间。
- 不写死任何绝对路径，一切从 `window.__CURATOR_BASE__` 拼（§2.3）。
