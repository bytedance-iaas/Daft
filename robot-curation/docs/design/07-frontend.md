# 07 前端设计

## 1. 技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 框架 | React 18 + TypeScript | 团队通用 |
| 组件库 | **Arco Design**（`@arco-design/web-react`） | 火山系设计语言，对齐控制台最省力 |
| 路由 | React Router 6 | 深链需要真实 URL |
| 数据层 | TanStack Query | 轮询、缓存失效、乐观更新都是现成的 |
| 构建 | Vite | 产物是纯静态，交给 Daemon serve |
| 图表 | ECharts（Arco 生态） | 技能分布、延迟分布、通过率 |
| 语言 | 界面中文，仅亮色主题 | 需求明确 |

**前端零业务状态**（D：后端保存状态，前端 stateless）：所有状态读自 API，
本地只存 UI 偏好（列宽、折叠、上次选的筛选项）。刷新页面不丢任何东西。

## 2. 页面与路由

| 路由 | 页面 | 说明 |
|---|---|---|
| `/tasks` | 任务列表 | 默认页，游标分页 + Lazy Loading |
| `/tasks/new` | 新建任务 | 含预检、模块选择、Episode 选择、VLM 配置 |
| `/tasks/:id` | 任务详情 | 状态、进度、模块表、Token、子任务、报告概览 |
| `/tasks/:id/report` | 质检报告 | 与模块一一对应的小节 + 性能剖析 |
| `/tasks/:id/adjudication` | 人工裁决 | 统一入口，按来源模块分组 |
| `/credentials` | 密钥与资源管理 | TOS 凭证、方舟后端、自定义端点 |

### 2.1 深链（契约不变）

`/tasks/new` 必须接受 v1 已上线的 GET 参数，**逻辑一字不改**
（源实现：`ui/runner.py::deeplink_values / deeplink_region / deeplink_endpoint`）：

- 数据集地址：`?dataset=` / `?dataset_url=` / `?url=`（三个键都认，可多值合并）
- 地区：`?region=`（只认地区字符集，URL 来的输入不可信）
- 端点：endpoint 键

行为：带参进来自动填好数据集地址、地区、交付目录，直接进「新建任务」，
用户只需补交付名即可开跑。rerun viewer 的「Diagnose」按钮依赖这个契约，不能破坏。

### 2.2 给 Agent 的反向链接

API 返回的 `links` 数组（见 `02-cli-contract.md` §6）指向的就是上面这些路由，
保证 Agent 拿到 JSON 后能一键把人带到正确的页面（报告/裁决）。

## 3. 新建任务页（最复杂的一页）

```
┌─ 基本信息 ────────────────────────────────────┐
│ *任务名称                                      │
│ *数据集来源  ( ) 私有 TOS  ( ) HuggingFace 镜像 │
│              ( ) 本地挂载路径 [experimental]    │
│ *数据集地址  [tos://...          ] *地区 [▾]    │
│ *访问凭证    [▾ 从密钥管理里选]                  │
│ *交付目录    [tos://...          ]  (失焦即写探针)│
└───────────────────────────────────────────────┘
        │ 地址填完 → 自动触发预检（防抖 600ms）
        ▼
┌─ 预检结果 ────────────────────────────────────┐
│ ✓ LeRobot v2 · 640 episodes · 3 cameras · 30fps│
│ ⚠ 未读到机器人型号，运动学极限需要补充           │
└───────────────────────────────────────────────┘
┌─ Episode 选择 ────────────────────────────────┐
│ ( ) 全部 640 条   (•) 自选                      │
│ [预览图网格，勾选]   或   [文本输入 3,10-12,34 ] │
└───────────────────────────────────────────────┘
┌─ 质检模块 ────────────────────────────────────┐
│ ☑ 时间戳检查   ☑ 运动质量   ☑ 视觉质量 …        │
│ ⚠ 运动学极限  [机器人型号 ▾ / 跳过]             │
│ ── 不支持的模块 ──────────────────────────     │
│ ☐ (灰) 精确去重   [详细信息]                    │
└───────────────────────────────────────────────┘
┌─ 模型配置 ────────────────────────────────────┐
│ *VLM 后端 [▾ ark-prod]  *模型 [▾]  思考强度 [▾] │
└───────────────────────────────────────────────┘
┌─ 高级（折叠）─ 重试次数 / 超时 / 并发上限 ───────┐
                              [取消]  [创建并开始]
```

要点：

- **必填项一律红色 `*`，提交前本地校验 + 提交后服务端校验双保险**（需求硬要求）。
- 预检自动触发，不需要用户点「检测」按钮；失败时就地给原因，不弹全局报错。
- 交付目录失焦时做一次**真实写探针**（v1 已有此行为，保留）：写不进去当场说，
  不要等任务跑到最后一步才失败。
- Episode 选择两种方式共存：预览图勾选 + 文本表达式（`3,10-12,34`），互相同步。
- 模块区的三态严格按 `availability` 渲染，标灰原因走「详细信息」弹窗，不截断成 tooltip 里的半句话。

## 4. 任务详情页

- 顶部：状态标签 + 进度条 + 操作按钮（暂停/恢复/停止/重试/重新导出）。
  按钮的禁用状态由 `state` 决定，非法操作前端就不给点（后端仍会校验）。
- 模块表：每行一个模块，状态、耗时、判决摘要、失败时的「重试」。
- **Token 消耗卡片**：prompt / completion / 请求数，按模块展开。不显示金额（D12）。
- 子任务时间线：什么时候重试了哪个模块、什么时候执行了裁决。
- **交付过期横幅**：`delivery_stale=1` 时置顶显示「判决已更新，交付数据集待重新导出」+ 按钮。

## 5. 质检报告页

- 概览卡片（通过率、拒绝原因 Top、耗时、Token）。
- **模块小节与勾选模块一一对应**，顺序按 `report.json` 的 `modules` 数组。
- 有待裁决条目的小节，右上角「去裁决（N）」跳 `/tasks/:id/adjudication?source=<module>`。
- 失败的小节显示错误 + 「重试此模块」。
- 明细表走服务端切片分页（100 行/页），排序字段限白名单。
- 性能剖析独立 tab：延迟分布、有效并发度、stage 墙钟占比、合并节省量。

## 6. 人工裁决页

统一入口，**按来源模块分组**，每条明确写「这是哪个模块要求人来判的、要判什么」：

```
┌ 来源：任务成败判定 · 32 条待判 ────────────────┐
│ episode 000034                                 │
│ [视频播放器，多机位切换]  [证据帧]               │
│ 系统说明：证据不足，弃权                         │
│ 你的判断： (判成功) (判失败) (拿不准)            │
└────────────────────────────────────────────────┘
┌ 来源：技能画像 · 标注分歧 · 12 条 ─────────────┐
│ 原始标注：Hang the towel on the hook           │
│ 画面描述：Take a towel from the sink...        │
│ 你的判断： (采纳新标注) (维持原标注) (拿不准)    │
│            (整条弃用)                           │
└────────────────────────────────────────────────┘
                     [保存裁决]  [执行裁决]
```

- 「保存裁决」只记录（可反复改），「执行裁决」才建子任务真跑。两者分开是刻意的。
- 视频/证据帧走 **TOS 预签名 URL 直连**，前端在 403/过期时自动重签重试。
- 被拒复议只对归因于任务成败判定的拒绝开放入口（其余硬门是终局）。

## 7. 密钥与资源管理页

仿 VKE 的 KV 页面。两类资源：

1. **TOS 访问凭证**：名称 + AK/SK + 地区。保存时做一次连通性校验。
2. **VLM 后端**：
   - 方舟：名称 + API Key → 保存后**自动拉模型列表** → 每个模型配 thinking effort、并行度。
   - 自定义：名称 + endpoint + 可选 API Key → **模型手填** + 同样的 effort/并行度配置。

列表页只展示 `payload_meta`（地区、endpoint、模型数），**永不回显密钥**；
编辑时密钥字段留空表示不修改。

## 8. 工程约定

- **所有表单必填项红 `*` + 校验**（需求硬要求，写进 lint 检查清单）。
- 错误展示三级：字段级（表单内联）、操作级（Message）、页面级（结果页），不混用。
- 长任务不阻塞 UI：所有写操作立即返回，靠 SSE/轮询更新。
- **SSE 不可用时自动降级为 5s 轮询**，用户无感。
- 所有面向用户的文案先过 [humanizer-zh](https://github.com/op7418/humanizer-zh) 的规则过一遍，
  具体做法：文案集中在 `src/locales/zh.ts` 一个文件里，提交前人工过一遍规则表；
  不引入运行时依赖。
- 时间一律显示本地时区 + 相对时间（「3 分钟前」），hover 出绝对时间。

## 9. 静态 HTML 预览（第一步交付）

按需求「先进行 UI 设计，用静态 HTML 进行预览，确定风格以后再进行实际开发」：

- **第一批两页定风格**：`任务列表` + `新建任务`。纯静态 HTML + Arco 的 CSS，
  假数据写死，不接后端。
- 你确认风格后再补齐：任务详情、质检报告、人工裁决、密钥管理。
- 静态稿放 `frontend/mockups/`，评审通过后再开 React 工程。
  样式与火山控制台的像素级对齐留到后期整合（你已明确不急）。
