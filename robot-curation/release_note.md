# 机器人数据 Curation v1.0 发布说明

**发布日期：2026-08-21**  ·  分支 `release/v1.0`  ·  标签 `v1.0.0`

v1.0 是机器人数据 Curation 托管服务的第一个正式版本。它接收 LeRobot 格式的机器人演示数据集，
跑八项自动质检，把拿不准的轨迹（episode）交给人裁决，最后产出一份可直接用于训练的交付数据集和
一份可追溯的质检报告。数据放在火山 TOS 对象存储里，质检时不用先把数据集整个拷到服务器上，
读到哪条算哪条；服务以 Web 质检平台 + 命令行两种方式使用。

## 亮点

- TOS 直读直写，不落本地盘：数据集在哪个桶就从哪个桶读，小文件用到才读，大视频边读边处理，不落本地盘；交付数据集的每个文件做好就后台上传到交付桶，传完即删本地副本。进出都不经本地盘，数据集与交付的大小都不受本地盘容量限制。
- 数据来源：可以来自用户私有的 TOS 桶（挂载的桶或其他桶的 `tos://` 地址）/ HuggingFace 镜像缓存桶（不是完整的镜像站，但包含某些常用的公开数据集）。
- 八项质检 + 三态判决：通过 / 拒绝 / 弃权，其中“弃权”的轨迹不直接判废，转人工裁决，避免误伤好数据。
  - 画面与动作质量打分：画面查糊、过曝、坏帧；动作查抖动、尖刺；逐项打分加权成一个综合质量分。
  - 多视角任务成败判定：默认基于火山方舟豆包模型，用户也可以部署自托管的 VLM 模型；多相机取证 + 多路复核 + 多相机仲裁。
  - 卡顿 / 静止时间线：每条轨迹上的哪一时间段手臂卡死、哪一时间段在静止都会被精确检测。
  - 视频-动作同步检查：逐相机核对画面与关节动作的时间轴，能分清是相机没拍到、视角造成的假错位，还是真正的视频-动作时间错位，只有真错位的轨迹才被筛掉。
  - 运动学极限检查：对照该机器人型号的规格表，检验关节位置或速度是否越过物理极限。
  - 精确去重：按字节精确比对，只剔除完全相同的重复的数据；同一任务、同一场景的多次重录不算重复，不会误删。
  - 技能画像，两级归类：按任务标注归纳出两级技能体系（类目从数据里涌现，不用预设词表），逐类给出条数、占比与归属轨迹；用来分析数据集结构，发现哪类动作偏少，有针对性地补采或增广。
- 人工裁决闭环：进人工裁决的轨迹一般有任务标注问题或任务成败问题，通过执行裁决后交付数据集自动修正。
- 与 rerun 可视化打通：从 rerun viewer 一键跳进质检平台，可视化数据集地址、地区、交付目录默认填好。

## 完整流程：质检 → 人工裁决 → 执行裁决

一次 `curation run` 通常不是终点。系统对拿不准的轨迹会诚实弃权，这些轨迹需要人过一眼；裁决完再执行一次，交付目录里的数据集才是修正后的终态。

```
  原始数据集 ──▶ ① 质检(curation run / 界面「跑质检」)
                    │  八项质检 · 标注审计
                    ▼
               交付目录: 报告 + passed 通过 / reject 拒绝 / review 待裁决 + 数据集
                    │
         没有待裁决 ─┴─ 有待裁决
            │              │
            ▼              ▼
        ✅ 交付完成    ② 人工裁决(界面「人工裁决」页)
                           │  一条轨迹一张卡: 标注分歧 + 成败弃权一次答完
                           │  只记录, 不改数据
                           ▼
                       ③ 执行裁决(curation rejudge / 界面一键)
                           │  按裁决重判, 改标 / 剔除落实到交付数据集
                           ▼
                       ✅ 终态数据集
```

1. **质检**：对数据集跑八项质检，产出三份判决清单（`passed.json` 通过、`reject.json` 拒绝、`review.json` 待裁决）、质检报告和交付数据集。拒绝的不进交付；待裁决的**暂留**在交付数据集里，等人定夺。
2. **人工裁决**：在报告页「人工裁决」里逐张卡回答两个问题——原始标注对不对（采纳系统的改标建议 / 维持原标注）、这条到底成没成。答案只落成裁决记录，不改数据。
3. **执行裁决**：按裁决记录重判：采纳的改标写进数据集的任务标注（溯源列标明来历），判失败的从交付数据集里剔除，质检报告、三份判决清单、技能画像同步更新。界面上一键执行，命令行是 `curation rejudge`；桶里的交付同样支持。裁决记录存在交付目录根上，同一交付再跑新一批时自动沿用。
4. **可选**：「任务失败复议」对系统判失败的轨迹可选复核，走同一条裁决 → 执行的路；技能体系调整后用 `curation reprofile` 重算老交付的画像。

## 数据接入

- **LeRobot v2.x / v3.x** 两代格式均支持，自动识别
- **TOS 直读**：元数据 / parquet 按需取回，视频按字节范围顺序读，数据集不落本地盘
- **数据来源二选一**：
  - **私有**：填 `tos://桶/前缀` + 地区。本实例挂载的桶直接从挂载盘读，不走网络；其他桶用本实例的 TOS 密钥在线直读
  - **字节 HuggingFace 镜像**：匿名只读的公共桶，目录与地区自动填好，界面只列出镜像里 LeRobot 格式的数据集（含版本、集数），不完整的数据集直接标 ⚠️
- **桶名 / 地区对不上立刻提示**：填完地址或切换地区即探测；地区选错时系统会到其他地区找该桶，并提示正确的地区
- **从 rerun 跳过来**：在 rerun viewer 里对一个数据集点「Diagnose」，质检平台会自动填好数据集地址、地区和交付目录，只需填交付名就可跑质检

## 八项质检与判决

| 功能 | 类型 | 查什么 |
|---|---|---|
| 时间戳检查 | 一票否决 | 时间轴单调、无重复、帧率合理 |
| 运动学极限 | 一票否决 | 关节位置 / 速度是否越过该机器人型号的物理极限 |
| 运动质量 | 打分项 | 平滑度、尖刺、路径效率、末态稳定、夹爪一致性、执行器饱和、卡顿 / 静止 |
| 视觉质量 | 打分项 | 糊、曝光、坏帧（逐相机，可配权重） |
| 视频-动作同步 | 一票否决 | 画面与动作的时间轴是否对齐；逐相机测量，并区分几种情况：相机没拍到、视角造成的假错位、真正的时间错位 |
| 精确去重 | 数据集级 | 按字节精确比对，只剔除完全相同的重复数据；同任务重录不算重复，不会误删 |
| 任务成败判定 | 一票否决 | VLM 判该条轨迹的任务到底做没做成 |
| 技能画像 | 数据集级 | 归纳出两级技能体系，逐类给出条数与占比；缺标注的轨迹补标注（调 VLM） |

- **漏斗式执行**：数值检查在前，模型调用只跑幸存者
- **两类检查，两种判法**：一票否决项（物理违规、时序错位、任务失败）违反即判废；打分项（运动质量、视觉质量）加权求和，低于阈值才判废
- **标注审计**：技能画像的附带产物，自动发现原始标注与画面不符的轨迹，交人工裁决
- **质检范围三选一**：「完整质检」跑全部八项；「快速质检」只跑不需要模型的六项（时间戳、运动学极限、运动质量、视觉质量、视频-动作同步、精确去重），不做任务成败判定和技能画像，几秒出报告；「自选模块」自己指定只跑或跳过哪几项

## 任务成败判定（VLM）

- **模型服务**：火山方舟托管模型（豆包 doubao-seed）
- **多视角取证**：每条轨迹多相机各自取证，多路仲裁后才下“成功”结论；孤证弱成功不放行，证据不足转弃权
- **在线状态自动探测**：模型服务是否可用自动检测，不可用的在下拉里标明原因
- **可复核**：每次模型调用的提示、证据帧、延时全部落盘（`details/`）；报告页「性能剖析」给出各类模型请求（取证、判定、描述生成等）的延时分布

## 人工裁决闭环

- **待你裁决**：一条轨迹一张卡，人工裁决标注分歧与成败弃权的轨迹；可同屏播放多机位视频
- **任务失败复议**：对系统判“失败”的轨迹可选复核
- **执行裁决**：裁决只记录不改数据；`curation rejudge` 按裁决重判并同步交付数据集（改标 / 剔除落实到终态数据集），支持桶里的交付
- `curation reprofile`：技能体系或判据调整后，按当前口径重算老交付的技能画像分布

## 交付与报告

- 交付目录 `<交付名>/<时间戳批次>/`，每个批次内含：
  - `passed.json / reject.json / review.json` 三份判决清单（通过 / 拒绝 / 待裁决，含每条轨迹各维度的读数）
  - `report.md` 质检报告：各环节统计（输入 / 判废 / 去重 / 交付 / 待裁决）、逐条判决与弃权原因、相机流健康度、技能画像、模型调用延时
  - `details/` 明细 CSV、证据帧、同步曲线、裁决用视频片段
  - `episodes_parquet/` 清洗后数据集（轨迹级），`lerobot_curated/` 质检后交付的 LeRobot 数据集
  - `run.json` 本次运行事实卡与实际生效的全部配置
- 交付根下 `human-decisions/` 人工裁决记录（跨批次累积）、`latest` 最近一次批次
- 交付在哪个桶，报告页就在哪看

## Web 质检平台

- **跑质检**：选数据来源与数据集（可多选 / 跑全部）、质检范围（完整 / 快速 / 自选模块）、模型服务；任务面板实时进度与日志，可随时停止
- **质检报告**：质检总览、Episodes（按通过 / 拒绝 / 待裁决筛选 + 逐条证据 + 多机位同播）、人工裁决、技能分布、明细（动作 / 视频打分、视频-动作同步、卡顿时间线、性能剖析、本次运行配置）

## 命令行

`run` 质检 · `rejudge` 执行裁决 · `reprofile` 重算画像 · `review-page` 静态审片站 · `prune` 清理旧批次 ·
`fetch` 从镜像拉公开数据集 · `public` 列公共数据集 · `backends` 模型服务状态 · `ui` 启动质检平台。
输入 / 输出都接受 `tos://` 地址；站点配置 `site.yaml` 叠加出厂默认，`--set` 单项覆盖。

## 部署形态

- 火山 VKE 容器部署；数据桶通过 TOS-FSX 挂载或直连；站点配置走 ConfigMap；API 密钥与界面凭证只存 K8s Secret
- 公网入口经 APIG 网关，界面 Basic 认证
- **一客户一实例**：不同客户不共用实例；一个网关可按路径分流到多个实例

## 已知限制

- rerun（`.rrd`）格式的质检本版本默认关闭（`ingest.rrd_enabled: false`），只支持 LeRobot v2/v3
- 命令行的 `--batch`（根目录下全部数据集一起跑）暂不接受 `tos://` 地址，请逐个数据集跑；界面上的「跑全部」对直连桶是支持的
- 字节 HuggingFace 镜像里部分数据集不完整（如视频为 0 字节、无视频），界面已标 ⚠️，这类数据集跑不出视频类检查

## 快速开始

三步走完一条完整链路（以 DROID 前 20 条为例）：

```bash
# 1. 质检: 对 TOS 上的数据集跑前 20 条完整质检
curation run --input  tos://你的桶/datasets/droid --input-region cn-beijing \
             --output tos://你的桶/deliveries/droid-20 --max-episodes 20

# 2. 看结果 + 人工裁决: 打开质检平台, 「质检报告」页选交付名 droid-20,
#    在「人工裁决」页逐张卡回答标注与成败问题(只记录, 不改数据)
curation ui --delivery tos://你的桶/deliveries --port 7860

# 3. 执行裁决: 按裁决重判, 交付数据集同步修正(界面「人工裁决」页也有一键按钮)
curation rejudge --delivery tos://你的桶/deliveries/droid-20 --delivery-region cn-beijing \
                 --input    tos://你的桶/datasets/droid        --input-region cn-beijing
```

第 1 步也可以全在界面上做：「跑质检」页填数据集目录与交付名，点「开始质检」。

完整用法见 `README.md`。
