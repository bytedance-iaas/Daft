# Curator v2 · UI 静态预览稿

对应需求账本 **F3.1**。目的只有一个：**确定视觉风格**。确认后才开 React 工程（F3.2）。

| 文件 | 页面 | 对应设计文档 |
|---|---|---|
| `tasks.html` | 质检任务列表 | `docs/design/07-frontend.md` §2、§4 |
| `task-new.html` | 新建质检任务 | `docs/design/07-frontend.md` §3 |

两页都是**自包含 HTML**（样式内联），双击即可打开，不需要构建。

## 手动验证步骤

```bash
# 在仓库根目录起一个静态服务（两页之间有跳转，用 http 打开体验完整）
python3 -m http.server 4173 --directory robot-curation/frontend/mockups
```

然后浏览器打开 <http://localhost:4173/tasks.html>，逐项对照：

**任务列表页**
1. 七种任务状态的标签配色：运行中（蓝，呼吸点）、已完成（绿）、部分错误（橙）、失败（红）、排队中 / 已暂停 / 已停止（灰）。
2. 「droid-200 抽检」行有「待裁决 32」徽标——这是任务完成但仍需人工介入的状态。
3. 每行「更多」下拉里的操作随状态变化：运行中给暂停/停止，部分错误给「重试失败模块」，已完成给「人工裁决」「重新导出」。
4. 底部点「加载更多」，行数递增、计数同步——演示游标分页 + Lazy Loading 的手感（不是页码跳页）。
5. 点右上「新建任务」跳到新建页。

**新建任务页**
1. 必填项都有红色 `*`。**清空「任务名称」后点「创建并开始」**：输入框标红 + 下方出现错误文案（演示表单校验风格）。
2. 「预检结果」卡片：绿色为识别成功，黄色为「未读到机器人型号」的追问。
3. 「Episode 选择」切到**自选**：展开编号输入框 + 首帧预览网格，点格子勾选，右上角「已选 N / 200 条」实时变化。
4. 「质检模块」三态齐全：
   - 正常可用（蓝框选中）
   - **运动学极限**：黄色警告态，内嵌机器人型号下拉与「跳过该模块」
   - **运动质量**：置灰不可选，注明「数据集缺少 observation.state 列」并给「详细信息」
5. 「高级设置」默认折叠，展开后说明并发与请求合并由后端自动优化，这里只设容错参数。
6. 底部操作条吸底，随选择实时显示「将质检 N 条 episode，开启 M 个模块」。

右下角的黑色浮标是预览稿标记，点一下可关闭。

## 设计口径

颜色与尺寸全部取 Arco Design 的设计 token（火山控制台同源）：主色 `#165DFF`、
成功 `#00B42A`、警告 `#FF7D00`、危险 `#F53F3F`，中性色 `#1D2129 / #4E5969 / #86909C / #C9CDD4`，
边框 `#E5E6EB`，页面底色 `#F7F8FA`；顶栏 60px、侧栏 208px、按钮与输入框 32px、表格行 48px、圆角 2–4px。

⚠️ 这份手写 CSS 只为预览存在，**不会进 React 工程**。正式开发用 `@arco-design/web-react` 组件库，
届时这里的 token 是对照表，不是代码来源。两页各自内联了同一份样式，改样式记得同步两处。

## 已知的刻意取舍

- 数据全是假数据，任何按钮都不发请求。
- 未做响应式：控制台类产品以 1440px 及以上为主。
- 与火山控制台的像素级对齐留到后期整合（需求方已确认不急）。

## 待确认（评审时请重点看）

1. 顶栏 / 侧栏的信息架构：目前只有「质检任务」「密钥与资源」两个入口，是否还需要「数据集」或「概览」。
2. 任务列表是否需要展示「质检模块」列，还是收进详情页。
3. 新建任务页是否要拆成分步（Steps）向导——目前是单页长表单。
4. 任务状态的中文叫法：「部分错误」/「已停止」/「已暂停」是否符合火山的术语习惯。
